  1. Zombie reaping & process teardown (critical memory leaks)
  Every exit() leaks the dead process's page tables, kernel stack, and all its physical pages. Every exec() leaks the old address space. A session that forks and execs a dozen
  commands slowly exhausts physical memory. This is the highest-impact correctness fix — sys_exit needs to walk and free the page table, waitpid needs a per-process exit-status
   queue (not a single slot).

  2. Pipe EOF
  When the write end of a pipe closes, the read end blocks forever instead of returning 0. Shell pipelines (ls | cat) hang. This needs the PipeWrite drop handler to wake any
  PipeRead waiter and set a closed flag that sys_read checks before blocking.

  3. VFS fd leak on exec
  exec() currently doesn't close VFS-backed file descriptors that were open in the old process image. The VFS server leaks open-file slots. Fix: sys_exec needs to walk the new
  process's fd table and call vfs-close on any VfsFile handles before replacing the image (or do it in the exec preparation path in libos, which already calls
  close_all_vfs_fds() — verify this actually runs before exec).

  4. Demand paging load/instruction faults
  Store-fault COW works. Load faults (exception 13) and instruction faults (exception 12) still panic instead of allocating a zero page. This causes crashes on programs that
  touch unmapped stack or BSS regions for the first time via a load.

  5. Shell command verification end-to-end
  Task #2 has never been ticked off. After all the fixes above, do a boot and exercise: ls /, cat /init, echo foo > /tmp/x && cat /tmp/x, ls | cat, pipeline with Ctrl+C. These
  will surface remaining issues in one pass.

  6. Network echo-server smoke test
  Run ./scripts/run.sh, start /echo-server in the VM, nc localhost 5555 from the host. If it connects and echoes, the full network path is verified and task #7 closes.
